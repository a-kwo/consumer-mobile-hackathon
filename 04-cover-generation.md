# Feature plan 4: Generated album covers

Written Nov 15, 2026. Read `PLAN.md` and `AGENTS.md` first. This depends on plan 3 (the `osts` table and file storage).

## Goal

Every OST gets a square cover in one recognizable Score style. The cover is generated by an image model from the day's scenes and genres, or built from a photo the user imports.

## Decisions already made

- Covers share one visual identity. The style is fixed by the app; the day changes the subject, palette and mood.
- An image model does the art. The candidates are Google's Nano Banana family and OpenAI's GPT Image 2.5 Sunburst.
- Users can import their own photo instead.
- The title and other text are drawn by the app on top of the art, not by the model. That keeps lettering consistent, legible and editable.
- A procedural ASCII cover (see the design canvas samples) is the instant placeholder and the fallback. It costs nothing and runs on the phone.

## The style system (`convex/coverStyles.ts`)

- `STYLE_PREAMBLE`: one paragraph that never changes and defines the look. Write it once the team has picked the direction (ASCII and terminal art is the current front-runner).
- `GENRE_PALETTES`: a two-color palette per genre (ground and ink), matching the canvas samples.
- `MOTIFS`: a subject hint per scene part. Rain gives streaks and puddles, late night gives a moon, a run gives motion lines.
- Prompt template:

```
{STYLE_PREAMBLE}
Subject: {motif for dominant weather}, {motif for dominant time of day}, {motif for dominant pace}.
Mood: {top 3 moods from the day's songs}.
Palette: {ground} background, {ink} foreground, two colors only.
Square composition. Leave the bottom quarter visually quiet.
No text, letters, numbers, logos or watermarks.
```

- The prompt uses only scene data and mood words. Never send place names, coordinates, display names or song and artist names.
- `songs` has no genre field yet. Add `genre` (one of about 12 values) to `pipeline/label.py` and the schema, or pick the palette from the dominant mood until then.

## Backend (`convex/`)

- `osts` fields (declared in plan 3): `coverStorageId`, `coverStatus` (`none`, `pending`, `ready`, `failed`), `coverMode` (`generated`, `photo`, `photoRestyled`, `procedural`), `coverStyle`, plus `coverAttempts` (number).
- `covers:request` (mutation): args deviceId, ostId, mode, photoStorageId (optional). Checks ownership and the caps, sets `coverStatus` to `pending`, schedules the action.
- `covers:generate` (internal action): summarizes the OST (dominant weather, time, pace, moods, genre), builds the prompt, calls the provider, stores the image with Convex file storage, sets `coverStorageId` and `ready`. On any error or refusal it sets `failed`.
- `convex/covers/provider.ts`: one function, `generateImage({ prompt, referenceImage?, size })`, returning image bytes. One implementation per vendor behind it, chosen by a Convex environment variable, so switching between Nano Banana and Sunburst is a config change.
- Keys are Convex environment variables (`npx convex env set`). Never in the app or the repo.
- Caps, in `tuning.ts`: 3 generations per OST, 5 per device per day. Proof runs on cloud devices use `procedural` mode only, so they cost nothing.
- Output: 1024 x 1024.

## Cover modes

| Mode | What happens | Model call |
| --- | --- | --- |
| `generated` | Art from the day's scenes | Text to image |
| `photoRestyled` | The user's photo redrawn in the Score style | Image edit with the photo as reference |
| `photo` | The user's photo as is, cropped square | None |
| `procedural` | ASCII art computed on the phone from the scene | None |

## App (`src/`)

- `src/components/Cover.tsx`: draws the art (stored image or procedural), then the overlay: Score mark, date, scene line and title in the app's type. One component for the OST screen, the feed and the share card.
- Cover sheet on the OST screen: "Generate", "Use a photo", "Restyle a photo", and "Try again" while attempts remain.
- While `coverStatus` is `pending`, show the procedural cover with a small progress state. `ost:get` is reactive, so the real cover appears on its own.
- Before the first photo restyle, show one line saying the photo is sent to a third-party image model, with a confirm.
- Port the ASCII generators from the design canvas into `src/lib/asciiCover.ts`, driven by the scene: rain density from weather, moon or sun from the hour, pattern spacing from BPM.

## Steps

1. `Cover.tsx` with the procedural mode and the text overlay. *Done when* every OST shows a cover with no backend call, including in a Revyl proof run.
2. Prompt template tested by hand on 10 scenes. *Done when* the team agrees the set looks like one family, and the preamble is committed.
3. Provider, `covers:request` and `covers:generate`. *Done when* tapping Generate on a phone replaces the placeholder with a stored image, and the time it took is written down here.
4. Photo modes: `photo`, then `photoRestyled`.
5. Caps, failure states and the consent line.

## Risks

| Risk | Fallback |
| --- | --- |
| The style drifts between covers | A tighter preamble; pass one fixed reference image with every call; lower variation settings if the API has them |
| Generation is too slow for a live demo | The placeholder shows at once; pre-generate covers for the demo OSTs and the seeded friends |
| The model adds text anyway | The overlay covers the bottom quarter; retry once with a stronger instruction |
| The model refuses a photo or a prompt | Set `failed`, keep the procedural cover, show a short message |
| Cost runs away | The per-OST and per-device caps; procedural mode for all test devices |
| Photos of people sent to a third party | The consent line; `photo` mode needs no model |
